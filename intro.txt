1. EXECUTIVE SUMMARY & SYSTEM IDENTITY
================================================================================
- Name: BlackyAgent (CLI commands: `blacky`, `blaky`)
- Tagline: Autonomous, Siri-like Personal AI Assistant for macOS & Mobile with 
  Full Execution Power.
- Core Identity:
  Blacky is not merely a conversational LLM chatbot. It is a visually intelligent,
  autonomous desktop operating agent that runs locally on macOS. It sees the 
  screen, understands open applications, navigates browsers, manipulates the file 
  system, controls WhatsApp Desktop natively, triggers Apple Shortcuts, controls 
  mobile devices, and talks back via natural speech synthesis.
- Primary LLM: a local Ollama model (default `qwen3.5:4b`) via the official
  `ollama` Python client at `http://localhost:11434`. Fully offline, no API key.
  An optional separate vision model handles screenshots.
- Target Platform: macOS (specifically optimized for Apple Silicon / Intel macOS 
  with AppleScript, System Events, CoreGraphics, Carbon, and AppKit bindings).

Key Design Principles:
1. "Understand First, Act Second, Verify Always": Every turn assesses the screen 
   state, performs minimal necessary actions, and verifies the outcome.
2. "Strict User-Intent Boundary (Zero Unsolicited Actions)": If the user asks to 
   "search", only search. Never automatically add to cart, click play, or buy.
3. "Never Auto-Select in Ambiguity": If multiple contacts, items, or variants 
   match, always ask the user to clarify. Never guess.
4. "Confirmation Before Consequence": Irreversible actions (checkout, deletion, 
   unprompted messaging) require explicit user approval.
5. "Direct Tool Calling": Bypass unnecessary intermediate steps (e.g. action tools 
   handle window focus and full screen internally for maximum speed).

There is no cloud fallback by design. At startup Blacky verifies that Ollama is
reachable and that `OLLAMA_MODEL` is installed, and exits with a clear message
(e.g. `ollama pull qwen3.5:4b`) instead of failing mid-task. Timeouts and
connection errors surface as a spoken/printed error.

5. CORE AGENT ORCHESTRATION & REASONING LOOP (blacky/core/agent.py)
================================================================================
The orchestrator is implemented in `BlackyAgent`. It follows a structured ReAct
pattern augmented by screen context and human-in-the-loop safety gating.

1. Manual Function Calling Loop:
   - Configured with `automatic_function_calling=False`.
   - Reason: The agent explicitly intercepts tool calls before execution to:
     a) Check if the tool requires user confirmation (e.g. deleting files, checkout).
     b) Enforce intent boundaries (preventing unsolicited messaging).
     c) Capture screen states after execution to verify success.
     d) Detect ambiguity markers returned by tools and pause for user input.
   - Maximum tool hops per turn: 15 hops (`MAX_TOOL_HOPS = 15`).

2. Task State Machine (`self.task_state`):
   - `phase`: "idle" | "executing" | "awaiting_clarification" | "completed"
   - `instruction`: The active root instruction being solved.
   - `stage`: "add" | "messaging" | "file_task" | "search" | "media" | "other"
   - `pending_question`: The question asked to the user if blocked.
   - `pending_candidates`: List of matched contacts, products, or options.
   - `pending_action`: Gated action `{"tool": name, "args": {...}}` awaiting "yes/no".
   - `awaiting_confirmation`: Boolean flag indicating confirmation block.
   - `selected`: The resolved choice once user clarifies.
   - `answers`: History of user clarification inputs for this task.

3. Ambiguity & Clarification Handling:
   - When tools return `AMBIGUOUS` or multiple matching contacts/products:
     * Phase transitions to `awaiting_clarification`.
     * The question is spoken and displayed.
     * The task pauses, preserving full state.
   - When the user answers:
     * Ordinal answers ("first", "second", "1st one", "3", "the second") map directly
       to the pending candidate list using `_ANSWER_ORDINALS`.
     * Fuzzy string and word-subset matching handles variant attributes (e.g., "750ml").
     * The agent seamlessly continues the task from the exact point of interruption.
   - Mid-task corrections: If the user changes their mind mid-task, the agent
     detects `_looks_like_new_instruction()` and updates the task plan dynamically.

4. Confirmation System:
   - Tools in `_CONFIRMATION_REQUIRED_TOOLS` (`delete_item`, `blinkit_checkout_flow`,
     `amazon_checkout_flow`) are NEVER called blindly.
   - Messaging tools (`whatsapp_send_message`, `mobile_send_imessage`) require
     explicit authorization in the initial prompt or confirmation before dispatch.
   - If confirmed ("yes", "proceed", "do it"), the agent executes the tool and verifies.
   - If rejected ("no", "cancel", "stop"), the agent terminates the action safely.

5. Verification Before Completion:
   - Guard against false "Done" claims:
     If the user asked to send a message, but no messaging tool was executed,
     `_verify_task_completion()` prevents the agent from claiming the message was sent.
     It keeps the task open and prompts the user for the missing contact name.

6. INVIOLABLE OPERATING DIRECTIVES & USER-INTENT BOUNDARIES
================================================================================
Defined in `blacky/core/prompts.py` (`SYSTEM_INSTRUCTION`):

1. STRICT USER-INTENT BOUNDARY:
   Work ONLY up to the exact boundary of the user's specific instruction.
   DO NOT PERFORM ANY OPERATION ON YOUR OWN!
   - Search vs. Add: "search Diet Coke on Blinkit" -> ONLY search and display results.
     ABSOLUTELY NEVER click ADD, add to cart, or proceed to checkout.
   - Open vs. Operate: "open WhatsApp" -> ONLY bring WhatsApp to the front and make
     fullscreen. NEVER send messages or start calls.
   - Media: "search songs on YouTube" -> ONLY search. NEVER click play unless
     explicitly instructed ("play bulleya on youtube").
   - Add to Cart vs. Checkout: "add milk to cart" -> Add item and STOP. Never checkout.

2. SINGLE DEFAULT BROWSER RULE:
   Blacky must operate EXCLUSIVELY on whichever browser is set as the macOS system
   default (detected dynamically via AppKit: Brave, Chrome, Safari). Never open or
   hop between multiple different browsers.

3. ENTIRE SCREEN (FULL SCREEN) MODE:
   Before automating any macOS window (WhatsApp, browsers, applications), Blacky
   ensures the application is in native macOS Full Screen mode via
   `make_window_fullscreen`. This guarantees standardized UI layout and coordinates.

4. SPEECH REPAIR & SELF-CORRECTION HANDLING:
   Spoken language often contains verbal repairs ("wait no", "scratch that", "actually",
   "I mean"). Blacky discards the mistake and acts ONLY on the final correction:
   * "message Rohan wait no message Rishab hello" -> Sends message to Rishab.

7. SCREEN AWARENESS & MULTIMODAL COMPUTER VISION
================================================================================
Blacky continuously observes what is happening on the user's monitor:

1. Context Telemetry (`get_screen_context()`):
   - Frontmost active application (via AppleScript System Events).
   - Active website / service (Blinkit, Amazon, YouTube, GitHub, WhatsApp).
   - Active browser URL and window title.
   - Extracted GitHub user and repository names if on github.com.

2. Visual Screen Capture (`capture_display_screen()`):
   - Captures `/tmp/blacky_live_screen.jpg` using macOS `screencapture`.
   - Sends the JPEG (base64) to the configured local vision model when available.
   - Enables the model to read screen text, verify UI layouts, and observe results.

3. Visual Animation States (displayed in terminal UI):
   - 🛰️ Observing Screen -> 🔍 Analyzing Interface -> 🎯 Identifying Elements ->
     🧠 Processing Instruction -> ⚡ Executing Action -> 🛡️ Verifying Action ->
     🎉 Task Completed (or ⏳ Waiting for User).

9. VOICE SUBSYSTEM: PUSH-TO-TALK STT & OPERATIONAL TTS
================================================================================
Voice Pipeline Architecture:

1. Speech-to-Text (`blacky/voice/stt.py`):
   - Mac Option (⌥) Key Push-to-Talk:
     Uses low-level macOS C bindings (`CoreGraphics.CGEventSourceFlagsState` and
     `Carbon.GetKeys`) to monitor the hardware Option key state.
     User holds Option while speaking; releasing it immediately triggers transcription.
   - Enter-to-Record Fallback:
     Press [ENTER] in terminal to record audio with dynamic terminal volume meter
     and automatic silence termination.
   - Phonetic Speech Normalization (`normalize_speech_text()`):
     Corrects common Indian English acoustic misrecognitions:
     * "hitler ki" / "hey blackie" -> "Hey Blacky"
     * "blanket" / "blickit" -> "Blinkit"
     * "rishabh" -> "Rishab" (owner's brother)
     * "avinash" / "avdhesh" -> "Avnish"
     * "diet book" / "diet cake" -> "diet coke"
     * "one crore packet" -> "Kurkure packet"
     * "a charlie flavour" -> "Achari Masti"

2. Text-to-Speech Engine (`blacky/voice/tts.py`):
   - Uses native macOS `say` binary with the "Samantha" voice at 195 wpm.
   - Operational Speech Filtering (`clean_text_for_speech()`):
     Blacky NEVER recites long dictated message bodies or code aloud over voice!
     It strips code blocks, URLs, markdown, and quotes, speaking only concise
     status announcements (e.g., "Calling Satyam on WhatsApp", "Folder created").

11. LAUNCHER SYSTEM & MULTI-TERMINAL DETECTION (blacky.sh)
================================================================================
The bash launcher `blacky.sh` detects the host environment and spawns tabs:

0. Automatic Ollama Daemon Startup:
   `blacky.sh` (as well as the Python CLI entrypoint) automatically checks if the
   local Ollama server (`http://localhost:11434`) is running. If not, it launches
   Ollama in the background (`/Applications/Ollama.app` or `ollama serve`) and waits
   until the API is responsive before continuing.

1. Host Environment Detection:
   Walks up the ancestor process tree (`ps -o ppid=,comm=`) to identify the host IDE:
   - Visual Studio Code
   - Cursor
   - Windsurf
   - JetBrains (PyCharm, IntelliJ)
   - iTerm2
   - Warp
   - Ghostty
   - Native macOS Terminal.app

2. Tab Spawning via AppleScript (`spawn_in_new_terminal()`):
   Can launch Blacky components into dedicated tabs:
   - `./blacky.sh --new-voice`: Spawns Push-to-Talk voice mode in a new tab.
   - `./blacky.sh --new-mobile`: Spawns Mobile Remote server in a new tab.
   - `./blacky.sh --new-chat`: Spawns REPL chat in a new tab.
   - `./blacky.sh --new-all`: Spawns both Mobile Server and Voice Mode in 2 tabs.

12. CLI ENTRYPOINTS & EXECUTION MODES

Registered CLI commands: `blacky` and `blaky` (configured in pyproject.toml).

Modes of Operation:
1. Interactive Chat REPL (Default):
   blacky
   Start a continuous conversational session with rich syntax highlighting.

2. Push-to-Talk Siri Voice Mode:
   blacky -v
   or: blacky --voice
   Speak commands using the Mac Option (⌥) key.

3. Mobile Remote Mode:
   blacky -m
   or: blacky --mobile
   Starts FastAPI server, Cloudflare tunnel, and displays terminal QR code.

4. Direct One-Shot Command Execution:
   blacky "create folder code and write a python quicksort script"
   Executes the instruction directly and exits immediately.

CLI Flags:
- `-v`, `--voice`: Push-to-talk voice mode.
- `-m`, `--mobile`: Launch mobile remote server.
- `-s`, `--speak`: Enable spoken responses (TTS) in text mode.
- `--no-voice`: Silence all voice output.
- `--port <PORT>`: Custom port for mobile server (default: 8000).

13. TEST SUITE & VALIDATION PROCEDURES
================================================================================
The project includes 48 unit tests in `tests/`:

Execute all tests:
python3 -m unittest discover tests

Test Coverage Breakdown:
- `tests/test_filesystem.py`: Tests folder creation, file writing, reading, editing,
  deletion, and directory listings in temporary sandbox environments.
- `tests/test_tools.py`: Tests tool registration decorator, argument logging,
  execution tracking, and default browser resolution.
- `tests/test_whatsapp.py`: Validates contact disambiguation, fuzzy match logic,
  "me/myself" detection, and message dictation cleaner.
- `tests/test_utils.py`: Tests string manipulation and palindrome helpers.
- `tests/test_agent.py`: Validates agent initialization, manual tool loop, stage
  classification, confirmation gating, and model fallback logic.

All 48 tests must pass with 0 errors before deploying modifications.

14. CRITICAL PITFALLS, EDGE CASES & HEURISTICS TO REMEMBER
================================================================================
For any AI agent modifying or operating BlackyAgent:

1. Never bypass the manual tool loop:
   The manual tool loop in `agent.py` is intentional. Do NOT hand execution back
   to automatic/unguarded tool running without re-architecting the confirmation
   gate, duplicate-call detection and screen verification hooks.

2. Disambiguation must precede execution:
   If a contact search matches multiple entries, NEVER select the first one.
   Always return the candidate list to the user and transition to
   `awaiting_clarification`.

3. Never touch Apple Messages for WhatsApp tasks:
   WhatsApp has its own native tool suite (`whatsapp_*`). Under no circumstances
   call `mobile_send_imessage` for WhatsApp requests.

4. Respect the Full Screen Rule:
   macOS UI element coordinates change drastically between windowed and fullscreen
   modes. Always call `make_window_fullscreen()` before performing GUI automation.

5. Keep Speech Responses Brief:
   When `speak_replies` is enabled, ensure voice output remains concise and
   strictly operational (under 160 characters). Never speak entire code listings
   or dictated paragraphs.

6. Temporary Files Location:
   All temporary screen captures belong in `/tmp/` (e.g., `/tmp/blacky_live_screen.jpg`).
   Never clutter the workspace with temporary image artifacts.
